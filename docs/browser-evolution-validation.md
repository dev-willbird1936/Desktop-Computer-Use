# Browser adapter validation

This slice adds a separate lazy Playwright adapter. Desktop startup registers `BrowserSessionManager` and does not call Playwright or launch a browser. The existing 12 MCP tools are unchanged. Jev is not involved.

Package: `Microsoft.Playwright` 1.62.0. Binding source pin: `microsoft/playwright-dotnet` commit `1920af3d88ddf85caef69e94b2692c17e072f4bd`.

## Covered

- Session modes: attached loopback CDP, dedicated persistent profile, and fresh isolated launch.
- Owned sessions close their context and browser. Attached sessions do not call browser/context close.
- Target identity includes session, context, page, main frame, and document epoch.
- Navigation changes the document epoch and old bindings fail closed.
- Selectors must match exactly one element. No `Force` and no caller-supplied JavaScript.
- Password observation text is omitted. Fill still accepts the exact caller value.
- One-level iframes are observed as `iframe-N`. Click and fill use that frame locator, so a same-label parent control is not selected.
- One nested iframe is observed as `iframe-N/iframe-M`. The action uses that inner frame. A same-label parent control is not selected.
- A third iframe is observed as `iframe-N/iframe-M/iframe-P`. A fourth iframe is observed as `iframe-N/iframe-M/iframe-P/iframe-Q`. The innermost control is the action target. Same-label controls in the outer frames stay unchanged. A fifth iframe level is rejected.
- One open shadow root is observed as `open-root:N>>selector`. The Nth open host that has an id is used. Light-DOM controls stay on `css:light`, so the same-label light control is not selected. A closed shadow root, a missing open root, and a selector containing `shadow` or `internal:` are rejected.
- The same open-root address works inside `iframe-M`. The click uses that frame's open host. A same-label control in the iframe light DOM and in the main document stays unchanged. A closed root in that iframe is rejected.
- One nested open shadow root is observed as `open-root:N>>open-root:M>>selector`. The inner control is the action target. A same-label control in the outer root and the light DOM is not selected. A third shadow level and a closed inner root are rejected.
- A popup page is observed as `popup-page:N>>selector`. N is the first-seen index, not the newest page. The opener page stays the action target unless that explicit selector is used. A missing popup index is rejected. Iframes inside a popup stay deferred. One open shadow root is addressed as popup-page:N>>open-root:M>>selector. One nested open shadow root is addressed as popup-page:N>>open-root:M>>open-root:P>>selector. Same-label controls in the outer root, popup light DOM, and opener remain unchanged. A third shadow level and a closed inner root are rejected.
- Owned sessions accept an absolute download directory. `browser_download` saves the browser file inside that directory and waits until that exact file is readable and stable. A sibling `.crdownload`, `.partial`, or `.download` file keeps the save incomplete. A suggested name such as `../note.txt` becomes `note.txt`. The wait fails when the timeout ends if the exact file is missing or still partial. Attached sessions reject a download directory.
- Owned sessions accept an absolute upload directory. `browser_upload` sets one absolute file inside that directory on a unique file input through Playwright `SetInputFilesAsync`. A relative path, a file outside the directory, and an attached session are rejected.
- `browser_dialog` clicks one unique control and answers only the JavaScript dialog that control opens. The caller names `alert`, `confirm`, or `prompt`, and chooses accept or dismiss. Accepting a prompt requires the exact prompt text. A mismatched dialog type is dismissed only so the page can continue, and the action fails. No standing handler dismisses later dialogs. Attached sessions are rejected. A `popup-page:N>>selector` request listens on that popup page only.
- A dedicated persistent session uses an absolute Edge profile. Closing the owned session and opening the same profile again keeps the page value stored by that profile. A different absolute profile does not see that value. A relative profile path is rejected. The launch uses the installed `msedge` channel and does not download a browser.
- An owned session can expose one explicit loopback debugging port. A second session attaches to that endpoint with `NoDefaults`. Closing the attached session does not close the owned browser context. The owned page stays observable. Attach mode rejects a debugging port.
- `browser_click` first asks Playwright’s no-dispatch `Trial` actionability check. It refuses detached, hidden, disabled, moving, obscured, or otherwise non-actionable targets before a real click; it does not force the click or fall back to foreground input. `browser_fill` and `browser_press` require one visible, enabled, non-read-only control but do not require pointer hit-testing, so an overlay alone does not block semantic input. Failure returns a typed error and dispatches no action. This readiness proof is browser-specific and does not assert native occlusion behavior.
- `browser_wait` supports `value_equals`, `text_equals`, `element_disappears`, `navigation_committed`, and `download_completed`. It uses Playwright locator waits or URL-commit events, a bounded 1–120000 ms timeout, and cancellation. It requires a current candidate for element predicates, rejects password value/text predicates, only watches a DCU-owned download, re-observes after the wait, and reports an unobserved timeout as `satisfied=false`, `outcome=unknown`. It does not use network idle or caller JavaScript.
- `browser_webmcp_discover` inspects `document.modelContext.getTools()` on the active page only. It retains only tools whose owner window and origin match that page. A bounded JSON Schema subset validates schemas and arguments. `browser_webmcp_invoke` re-discovers the registration before execution. Missing, changed, invalid, insecure-origin, or unsupported discovery uses an explicitly supplied browser candidate. A tool that starts but fails is not retried as a click, avoiding duplicate side effects. Current coverage is imperative only; the live fixture supplies a `document.modelContext` shim and does not prove native WebMCP support in installed Edge.
- Additive MCP tools: `browser_open`, `browser_observe`, `browser_click`, `browser_fill`, `browser_download`, `browser_upload`, `browser_dialog`, `browser_wait`, `browser_webmcp_discover`, `browser_webmcp_invoke`, `browser_close`. The original 12 tool names remain.
